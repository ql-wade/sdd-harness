# ADR-0022：升级 Comet 0.5.0，以原生组合应用替代自建补丁链

- 日期：2026-10-26。
- 状态：**Accepted（2026-10-26 用户批准实施）**。Kt 落点选 B1（保留最小补丁）。
- 证据与对比：[0.5.0 采纳提案](../../research/2026-10-26-comet-0.5.0-adoption-proposal.md)、[Classic 深挖](../../research/2026-10-26-comet-classic-workflow-deep-dive.md)。

## 问题

ADR-0021 已取消六角色常驻服务与私有 RPC/Runner 镜像前置，但门禁实现仍依赖 0.4.5 补丁链（0001–0004，约 4700 行），深度绑定上游内部（classic-store/hook-guard/archive 事务体）。0.5.0（2026-10-22）官方化了组合应用机制（replacements/extensions/checkpoints/verdict 协议），覆盖了我们自建补丁的主要动机。需要决定基线与门禁实现路线。

## 决定（待批准）

1. **基线升级至 Comet 0.5.0**（精确锁 commit/完整性，沿既有 `tools/comet` 供应链流程重建；本仓库无活跃 `.comet` 状态，迁移成本≈0）。旧 0.4.5 vendored 构建与全部历史证据原样保全。
2. **门禁表达改为官方 classic-full 组合应用**：base=classic-full；replacements 替换执行技能为 Matt 方法版（保留原 stepId 与输出契约）；extensions 落 R（open.evidence）、A/T（design.evidence）、P（build.plan.evidence）、V（verify.check.evidence 业务判据）、Kp（verify.check.evidence，归档期 validateOutcome 复验）；必需命令身份走原生 check-policy v2。组合包经官方编译器产出（确定性字节摘要）；validators 经 bindings.mjs 指向既有 `lib/delivery/*` 宿主侧纯组件。
3. **补丁链处置**：0004 删除（上游已含）；0001 缩为打包配置与防复装断言；0002 大幅收缩为声明式扩展；仅保留 0003 后继最小补丁（Kt 阻 completed），见开放决策。
4. **不建平行工作流、不 fork 源码**：不使用 Workflow Creator 生成新流程；不自建状态机/存储/锁（0.5.0 FileRuntimeStore/coordination 原生承担）；机器检查、用户审批、归档领域步骤保持官方不可替换。
5. **供应链不变项**：OpenSpec 隔离钉版经 `COMET_OPENSPEC` 注入（上游仍 @latest 无 pin）；全部依赖精确 pin；Node 钉版纪律不变。~~钉版 1.11.0~~→**2026-10-27 显式升级至 1.15.0**（当前稳定版，用户批准；兼容闭包谓词实测通过，C08 阳性；宿主全局 1.14.3/1.15.0 漂移如实登记不自动升级）。

## 开放决策（批准时一并拍板）

- **Kt 落点**：B1 保留最小补丁维持原语义（归档先行、Kt pending 同 Run 推进、Kt 完成才 completed）【推荐】；或 B2 零补丁（Kt 前置到 verify 检查点，知识发布延迟将阻塞归档）。

## 后果

- 正面：删除最大两块自建面；B1 检查身份/B4 逃生门获原生答案；与上游 SDK 主线对齐；组合包字节摘要可审计。
- 负面/成本：comet-executor/comet 适配器改写、delivery-case RED 重建、供应链一次性重锁；129/103 验收分母不继承，按原 oracle 重跑；保守失效负例需逐条重放证明等价。
- 覆盖关系：本 ADR 细化 ADR-0021 的门禁实现边界，不改变其单主控/知识/权限/恢复决策；ADR-0015 定位不变。

## 迁移（批准后按提案 §6 顺序）

供应链重锁 → 组合包编译验证（含 comet-design 可替换性实测）→ 适配器改写 → 受管 init → 计划 replan（P2_4/P1_6/P3_4/P1_4 改写，身份保留）→ 暂停现场一并处置。
