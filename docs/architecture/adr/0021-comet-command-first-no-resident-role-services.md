# ADR-0021：原生 Comet 命令流程，取消六角色常驻服务前置

- 日期：2026-10-26。
- 状态：用户已明确选择的架构收敛决定；本次只交付更新架构与计划。未执行代码删除、容器清理、部署或新流程验收。
- 权威设计：[Comet 命令与知识流程](../comet-ai-devops-convergence.md)。同一实施 Change 为 delivery-foundation-rearchitecture。

## 问题

旧方案把作者、测试作者、Reviewer、Publisher、Isolator等职责过早部署成六个常驻Docker服务，并把固定Runner镜像、签发体系、自建app-server通信与大量资格化作为接通业务流程的前置。已有组件测试不能证明真实命令、技能、知识与门禁已贯通；该部署拓扑对首版没有必要。

## 决定

1. 用户使用原生 `/comet` 与五个阶段入口。Comet原Run/phase/锁/事务是唯一业务状态权威；不新建阶段、队列、调度服务或第二进度源。
2. 模型、技能、子Agent、Shell、MCP和工具权限由现有Agent宿主提供。职责分离通过真实独立会话/执行记录、原生只读/工具权限与独立审查实现，不强制六个常驻容器、六个OS主体或自建Agent RPC网关。
3. 硬门必须程序化接入所有实际推进/归档/恢复入口，消费当前制品、真实执行与独立审查证据；不能退化为提示词或文件存在检查。宿主不能强制的能力如实标缺口，选择已支持宿主或有权人受控处理，不假称同用户签名能抵抗本机管理员篡改。
4. Docker只承载确有运行需要的Outline及其数据库/Redis、按选型需要的附件存储、deepwiki-open等基础设施；LLMWiki默认项目目录与宿主启动的stdio MCP，CodeGraph可选关闭。临时测试/构建作业可按真实需要隔离，不是六个常驻角色服务。
5. 不将自建app-server transport、72项配置闭包、统一签发服务、独立Control API、常驻controller端口或完整Runner重建作为命令流程的前置。现有普通CLI/原生工具能力优先，已有通用校验/路径安全实现按实际调用复用。
6. R、A、T、P、测试自动化、实现、V、Kp、规格归档、Kt仍严格分开。需求/设计变更保守失效全部下游，旧字节不复活旧票；Kp阻归档，Kt阻整体完成；真实源权限/预授权/受众/版本、未知发布结果及维护恢复不取消。
7. 先在现有宿主打通真实R→A→T→P→测试/实现→V，再接真实Kp→唯一归档→Kt；必要基础设施按此需要接入。不能先把所有基础设施/容器资格化再开始这条切片。
8. 原39节点、30父任务、69工作包、104场景、130检查身份保留；本期仍129/103，F10正向另期。I02改为退休常驻角色部署与可选临时作业边界；相关检查按宿主/命令证据重写，不把退役记PASS或丢弃记录。

## 覆盖与兼容

本决定覆盖ADR-0019/0020及原设计中“固定受管Runner、六角色OS/container隔离、签发服务/自建协议为首版必需”的部分。其单主控、知识边界、权限、独立验收、R10保留和G15正常依赖下发现3分钟/隔离2分钟目标不变。ADR-0015基础scaffold定位不变。旧架构票不冒充新摘要的技术批准；正式A门/必要独立审查由后继按新包执行。

## 迁移与风险

只在后继实施时分步从默认安装/启动/检查链移除旧六角色服务及其强制前置，保留旧Run、证据、镜像识别、卷和知识数据。先盘点与备份，再按明确范围停止/删除无用容器；删卷、覆盖知识或真实外部写不在本次文档授权中。

风险是过度简化成“Agent说完成就推进”。以共同Guard、真实调用轨迹、当前版本、独立审查和CI/资源端权限补齐，不以新增常驻服务补齐。按原唯一计划执行，任何旧fixture或镜像绿色都不能认证新流程。
