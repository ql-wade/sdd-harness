# Comet 原生命令驱动的 AI DevOps 与知识流程

> 当前目标架构：2026-10-26命令优先修订，依据用户明确决定及[ADR-0021](adr/0021-comet-command-first-no-resident-role-services.md)。仅完成设计/计划修订，尚未实现或验收。执行只用原Change的tasks/DAG/contract；旧六角色部署方案不再是当前实施依据。

## 1. 目标与唯一主控

目标是让团队在现有Claude Code、Codex等宿主中，用明确阶段命令调用合适的方法，经硬门禁完成AI研发与知识闭环。Comet管理原Run、阶段、结果接纳、返工、恢复和完成；宿主提供模型、技能、子Agent及工具；TeamAI只分发资产。

```text
用户 /comet 或原生阶段命令
  → Comet原Run与当前步骤
  → 现有宿主实际调用技能／独立Agent／工具
  → 正式制品、原始执行结果与独立审查
  → 同一Guard判断：推进／返工／等待／恢复
  → LLMWiki Kp → OpenSpec唯一归档 → Outline Kt
```

不新增六角色常驻服务、独立controller端口、业务API、调度队列、第二Run账本或Agent通信平台。无需用Docker部署Comet才能使用命令。已有源码扩展仅按缺失的门禁/恢复能力最小保留；优先原生支持，不因旧代码复杂而把它升为产品要求。

## 2. 命令、方法、产物与硬门

这些是原生阶段Skill入口，不是新的shell子命令。`/comet`负责配置路由/恢复；手动阶段入口也要重核状态，不能直接跳阶段。

| 入口／步骤 | 实际配合 | 正式产物 | 退出门与返工 |
| --- | --- | --- | --- |
| `/comet-open` · R需求澄清 | grill-me、需求作者与有权确认者；按权限检索知识 | 目标、范围、AC、非目标、环境、需求revision | 关键问题闭合且范围确认；未过R拒绝正式架构，范围问题回owner |

A与T分别过门，P、测试自动化和实现分别留证。运行时必须显示`当前phase／子步骤／已过门／阻塞原因／下一动作／Run与制品revision`，不得只显示一个模糊的“Comet处理中”。通常自动推进，人处理关键决定和真实阻塞；用户指定阶段不授予跳门权。

## 3. 硬门的实现边界

共同判定覆盖正常命令、直接transition、next/resume、适用hook写入口、archive和completed。Prompt指导执行方法，代码/宿主工具权限与受保护CI约束放行；缺任一实际入口覆盖就是未完成。

门证据至少包含原Run/action、当前需求/设计/TestPack/候选版本、实际执行/审查会话或平台记录、方法版本、原始结果引用及摘要。来源优先现有宿主真实执行事件、测试进程/CI和资源端读回。模型自写role/pass、技能名、文件存在和一个本地自签JSON不构成独立性。

使用宿主原生只读、工具/路径范围与平台授权保护控制文件及发布权限。Reviewer/Whitebox是独立实际执行，不能由Builder换标签充当；不要求一个角色一个常驻容器。没有宿主来源或强制权限证据时阻断对应操作或选择有能力的宿主/有权人，不能宣称抵抗同OS管理员任意篡改，也不因此自建RPC/签发平台。

需求/设计改变后保守失效全部下游；已观察的失效保持单调，恢复旧字节不复活批准。知识正文由真实作者生成后冻结，再独立审查；不要求作者预知正文digest。合法知识输出在V前通过原check-policy的精确outputs声明，完整policy摘要仍绑定；不能事后排除产品源码、CODE、授权、来源或受众来保住旧V。

## 4. 知识、权限和恢复

| 权威 | 内容与边界 |
| --- | --- |
| OpenSpec/Git | 正式需求、设计、测试意图、任务、决策和版本，不把检索结果当批准 |
| LLMWiki | 单项目可复用精华和引用；默认宿主stdio MCP＋项目数据，不承担团队ACL或阶段状态 |
| Outline | 团队精华与跨项目经验；继承真实源权限，跨项目单独审核发布，不收整仓代码/所有聊天 |
| deepwiki-open | 自托管、固定repo/commit的代码解释，不签正式架构与需求 |
| CodeGraph | 可再生结构/影响事实，默认可关闭，关闭不阻正确流程 |

R/A前检索；验证后提炼候选；Kp阻归档，Kt阻整体完成。Git规范与Outline正文各有权威，禁止复制成两个可独立更新的规范源。

保留已有预授权边界：登记且权限可核验的资料域和受管Outline文集；内容、源权限交集、完整目标受众、版本、grant每次写前重核。作者不能自批或更改权限策略。优先已有连接器身份/SecretRef，禁止从数据库抄owner key、把新密钥transport作为默认前置或把服务账号能读当作披露授权。

未知写结果只观察原Run/operation/目标ID，不因超时重建页面。发布后源撤权、受众变化和授权过期，经事件＋周期核验交回同Comet维护入口。可复用现有CI定时任务/宿主定时器触发原命令，触发器不拥有业务状态或重试调度。正常依赖下发现≤3分钟、隔离≤2分钟；故障暴露/告警/隔离分别计时，不把告警当隔离。

保留原Run锁/事务及归档前后位置解析、单一写者；中断后先核原进程与远端结果。备份覆盖原Comet状态、知识DB/附件和未完成义务；R10保留未完成唯一工作区。上述行为不依赖常驻controller容器；需持久任务时复用已有宿主/CI设施调用同入口。
