# Comet 交付系统 — 用户使用指南

> 版本：2026-10-27 | 基于 Comet 0.5.0 组合应用 | 适用于团队成员

## 一分钟上手

```
/comet-open "我想加一个导出功能"     ← 开始
/comet                             ← 随时看进度/恢复
/comet-archive                     ← 交付完成
```

就这三个命令。系统自动走完需求→架构→测试→实现→验收→归档。

---

## 五个阶段命令

### 1. `/comet-open` — 需求澄清（R）

你说需求，系统追问直到清楚。

| 系统会问你 | 你需要回答 |
| --- | --- |
| 目标是什么？ | 一句话描述想实现什么 |
| 范围？ | 做什么、不做什么 |
| 验收标准？ | 怎么判断做完了 |
| 环境？ | 需要什么工具/服务 |

**通过条件**：关键问题全部闭合 + 你确认范围。

**如果没过**：系统会告诉你缺什么，补齐后再推进。

### 2. `/comet-design` — 架构设计（A + T）

系统自动完成：
- **架构审查**：你的设计会经过独立评审投票（至少 3 票通过）
- **测试设计**：为每条验收标准设计测试用例和边界条件

**你做什么**：在系统要求确认时点"确认"或提修改意见。

**通过条件**：独立共识全票 + 测试设计独立审查通过。

### 3. `/comet-build` — 计划与实现（P → TDD → 审查）

系统自动完成：
- 生成实施计划（任务分解、依赖关系）
- 按计划逐任务 TDD 开发（先写测试、跑红、实现、跑绿）
- 每个任务完成后独立代码审查

**你做什么**：确认三选一（执行方式/TDD模式/审查级别）。

**通过条件**：全部任务完成 + 真实测试通过 + 审查无阻塞问题。

### 4. `/comet-verify` — 独立验收（V）

系统自动完成：
- 独立白盒验证（不是实现者自己验证自己）
- 逐条验收标准真实执行
- 类型化数据读回（不是只看"通过"两个字）

**通过条件**：所有必需场景真实执行且通过、零跳过。

**如果没过**：系统会精确告诉你哪条不过、差什么，修复后重新验证。

### 5. `/comet-archive` — 交付归档（Kp → 归档 → Kt）

系统自动完成：
- **项目知识提炼**：自动总结本次变更的可复用经验
- **规格归档**：验收通过的变更合并入主规格库
- **团队知识发布**：经验发布到团队知识库

**你做什么**：确认归档选项（五选一）。

**通过条件**：知识正文完成 + 规格归档 + 团队发布读回一致。

## `/comet` — 万能入口

任何时刻不知道该干什么，输入 `/comet`：

```
系统显示：
  当前阶段：build（实现中）
  已过门：R ✅ → A ✅ → T ✅ → P ✅
  当前任务：3/7 完成
  阻塞：等待你确认 TDD 模式
  下一步：选择 TDD 模式后继续
```

中断后恢复：直接 `/comet`，系统从断点继续，不重复已完成的工作。

## 门禁规则（你需要知道的）

| 规则 | 含义 |
| --- | --- |
| 缺门不放行 | 跳过需求直接设计 → 被拒绝 |
| 旧证据失效 | 设计改了但还用旧的审查票 → 被拒绝 |
| 零证据≠通过 | 测试全跳过 → 不算通过 |
| 显示≠事实 | 系统显示"成功"但读回不一致 → 被拒绝 |
| Kp 阻归档 | 项目知识没写完 → 不能归档 |
| Kt 阻完成 | 团队知识没发布 → 不能标记完成 |

## 常见问题

**Q: 我能跳过某个阶段吗？**
A: 不能。但小改动可以用 `hotfix` 或 `tweak` 模式（跳过设计阶段，直接进实现）。

**Q: 中断了怎么办？**
A: 直接 `/comet`，系统从断点恢复。不需要记住之前做到哪了。

**Q: 审查打回了怎么办？**
A: 系统会告诉你具体问题，修复后重新提交。打回次数有上限（3次），超了需要人工介入。

**Q: 多个人能同时用一个 Change 吗？**
A: 不能。同一 Change 只有一个写者。需要并行就开多个 Change。

**Q: 我的代码在哪？**
A: 实现在当前仓库。系统只管流程和门禁，不改变代码位置。

## 初始接入（管理员一次性操作）

```bash
# 方式一：从模板仓库（推荐新项目）
复制本仓库为模板 → bash tools/bootstrap.sh → 手动建 .comet/config.yaml

# 方式二：已有项目（增量注入）
领取 foundation 分发包 → SDD_TARGET_ROOT=<项目> bash tools/bootstrap.sh
→ 手动建 .comet/config.yaml → comet application install <组合包>
```

接入后日常使用只需要 `/comet` 系命令。
