# 知识预授权、权限继承与防自批契约

日期：2026-10-19。状态：Grill 设计，尚未实现。

## 0. 已确认边界

G04 用户选择 A：预授权范围内独立审查通过后自动发布；超范围或敏感内容交有权人。R01 固定受管 Runner、Comet 单一主控、R06 关闭与 R09 保守失效继续适用。

本契约不授予 Agent 签发授权、扩大源受众或更改目标分享设置的权力。具体 owner、委托、源实例和文集 ID 尚待登记。本轮未查询私有资料权限、签发授权或写入 Outline。

## 1. 谁签发、谁审查、谁执行

| 权力 | 有权主体 | 边界 |
| --- | --- | --- |
| 源资料提炼、处理与再发布授权 | 源项目/资料 owner 或其可核验委托的数据 steward | 知识库管理员不能代源 owner 授予源权利；可读不等于可导出/转载 |
| 目标空间写入和受众边界 | 团队知识域/Outline 空间 owner | 不能反向扩大源授权；不按文集名字猜受众 |
| 固化可验证的预授权 | 受保护授权配置/审批链，经可信 CI 签发凭证或认证批准记录 | 核验真实 approver 的域权限、批准内容版本和受保护来源；不信任待发布分支的自签结果 |
| 知识候选编写 | author Agent | 仅取获准材料、写候选；不能签 grant 或持有通用正式发布凭据 |
| 内容质量与敏感风险审查 | Runtime 派发的独立只读 reviewer | 审查通过不创造数据授权；不得作者改 role 自审 |
| 核验和正式发布 | Comet 可信检查器与受控 Publisher | 消费授权、审查和当前事实，不自授权限，不另立业务主控 |

同一人若确实拥有源和目标两类权力，可以在一个可验证审批中确认两者，不为形式强制多加人员。真实身份和职责/委托在可信 owner registry 登记，不能靠候选 frontmatter 的 owner 字段注册自己。

## 2. 最小签发形态（建议）

复用 Foundation/治理 Git、既有身份与 CI：源 owner 和目标 owner 审核受保护授权配置；可信工作流验证批准主体、权限/委托、批准对象版本，输出可验证授权凭证。Comet 核对登记的 issuer/workflow、受保护来源、摘要、有效期和撤销状态，不只检查签名存在或 PR 已合并。

owner registry、委托、签发工作流、验证器和授权配置本身受保护，不由作者分支控制。签发密钥/工作负载身份与 author/reviewer/publisher 隔离，Publisher 也没有签发根权力。使用现有平台证明，不自研密码学或新建审批主控。

grant 可以预先覆盖明确资料域和用途；每次发布仍须针对当前内容、源/目标权限和审查结果生成本次操作的发布判定回执。授权不自动续期，撤销/过期/职责失效不能由 Agent 修改时间或复制旧凭证绕过。

## 3. 预授权必须声明的范围

以下是拟议语义，不是当前原生配置字段：

| 类别 | 必须限定 |
| --- | --- |
| 主体/有效性 | grant ID/版本、issuer/approver 真实 ID、authority/delegation、签发/到期/撤销 |
| 来源 | 实例/租户、项目或资料域、资源 allowlist/受控筛选，禁止任意外部 URL |
| 用途/处理 | 允许的精华知识类型、处理环境和资料外发 profile；可发布摘要不自动授权向任意工具外发全部原文 |
| 内容 | 敏感级别上限、禁止类别、附件/引用范围、脱敏与摘录要求；作者不能自标 public 降级 |
| 目标 | Outline 实例/租户、集合/父节点、身份/受管组和允许可见性，默认不建公网 share |
| 动作 | 哪些对象可创建/更新/发布；不默认含改权限、加成员、公开分享、移出集合或删除 |
| 质量/证据 | 独立审查与检查器/策略版本、来源完整性、真实权限和内容摘要、读回 |
| 生命周期 | 权限新鲜度、撤回/过期处置、保留期限、发布后再验证与消费限制 |

候选不匹配时停止，不能让作者临时扩大 allowlist/受众/用途来过门；授权变更须按原签发路径形成新版本并失效旧判定。

## 4. Comet 的发布核验链

1. **授权链**：核验 issuer/workflow、批准主体的源/目标权力和委托、grant 版本/摘要、有效期与撤销。Agent 自写 grant.json 或 approved:true 无效。
2. **实际来源**：由受管检索/输入记录收集进入本次提炼的真实源对象和版本，不能只信作者末尾引用。未登记材料进入上下文就停止自动发布，补合法来源/授权；不能通过漏写引用隐藏受限输入。
3. **源权限与用途**：在线取得 Git/飞书等源当前可见性、成员/组/部门/外部访问和导出/处理约束。服务账号读得到，不证明目标成员有权读或该资料可再发布。分页不全、principal 未解析、权限错误均阻断。
4. **目标有效受众**：核对 Outline 集合默认权限、父级继承、用户/组、单页/子树分享、公网/外部路径等实际读者；不只比 collectionId。跨系统身份需可信映射，不按同名群/邮箱猜测。
5. **内容版本与独立审查**：标题、正文、附件/来源链接、目标和可见性作为冻结 payload；审查与扫描绑定同一摘要。reviewer execution/attempt 由 Runtime 登记，不接受作者自审或角色标签冒充。
6. **写前复核**：正式发布前再次核对授权、源/目标权限、payload 和当前输入，登记 operation/稳定 document_id。Publisher 只执行已验证的固定对象/动作，作者没有可绕过的通用写代理。
7. **独立读回**：核对实际内容、版本、集合/发布状态和授权范围，才接纳 Kt；未知/冲突/权限变化保留未完成并调和原操作。

长审查完成时和正式写入前都重新核对；批准后改内容、附件、来源或目标使旧判定失效。内容规范化必须可复现，不能靠模型说“意思一样”保留旧授权/审查。

## 5. 自动发布的受众规则

```text
目标有效受众 ⊆ 预授权允许受众 ∩ 所有实际来源允许披露受众的交集
```

多源取交集，不取并集。允许披露受众由当前源权限、用途/导出限制和有权 owner 的批准共同决定；不能将 read ACL 当任意转载许可。

超出边界时转人工，但必须是拥有对应源数据权力的人，对明确派生内容版本、受众和用途作分享/脱敏授权；知识库管理员或通用“接受风险”按钮不创造这种权力。密钥等禁止类别不能靠普通人工确认外发。

概括、翻译、去掉项目名不自动降低敏感性。独立审查和扫描均是证据，不是永不泄露的证明；分类未知、来源冲突或疑似敏感时停止自动路径。

## 6. 防自批必须靠隔离

作者只读允许资料并写候选；Reviewer 只读；Publisher 持必要目标写权限；issuer 独立。普通 Agent 不能写可信策略/批准/Runtime、读取签发密钥或得到超范围 token。同 OS 账户任意写目录加一句“不要自批”不能构成此保证。

不要把未经审核的草稿先写进更大受众的 Outline 集合；草稿保留在源授权范围内，publish=false 不是通用隐私保证。正式 Publisher 不暴露任意 URL/集合/ACL 修改入口，实际服务账号也只拥有必要权限。

这些均在固定 Runner 的受管边界中接入同一 Comet Run，检查器不派发业务，Hook 不签 grant 或发布。外部人工管理员直接更改源/目标 ACL 属于需再验证的权限事件，不能伪装成 Comet 永久控制了平台。

## 7. API 能力与持续继承的限制

官方 GitHub collaborator API 的列表涵盖直接、团队、组织默认权限、owner 等，且有分页/调用权限要求；不能只取 direct 或一页。飞书有协作者与公共权限入口，但本轮网页无完整正文，未试源实例，企业导出等完整权限解析尚待连接器实证。

Outline 文档说明单页/子树分享叠加集合权限；当前 OpenAPI 有 documents/collections memberships、group_memberships、groups.memberships、shares.list 等入口。API token 的观察完整性、父级继承、特权角色及所选部署版本都需要测试；不能因为接口存在就宣称已计算完整权限闭包。

源与目标 ACL 不能跨系统原子锁定。一次发布检查不保证未来永远同步；源撤权、组变化、额外分享需要受管空间/身份映射、事件或周期核验和撤回路径。Comet 可控制本次写入，不能凭 Kt 回执控制所有未来 Outline Web 访问。已下载副本无法承诺收回。

首版建议仅让“显式登记且权限可核验的项目资料域 + 专用受管 Outline 空间”自动发布。不能证明权限闭包/持续撤权的动态细粒度资料，先留受控链接或由有权人明确分享，不宣称自动源权限继承已完成。

## 8. 待执行的拒绝实验

伪造/过期/撤销 grant；有签名但 issuer 无域权限；作者自审；服务账号可读而目标无权；多源取并集；分页不全/未映射身份；审批后改 payload/附件/目标；继承/单页/公开分享扩大受众；403 当空集合；审核后源 ACL 收缩；普通 token 可改权限；未知敏感；远端未知/冲突；已发布后新增分享路径。

目前原生 Comet 与知识后端均未被证明已提供本契约。需要受保护授权、薄权限/发布适配、全入口 gate 和真实隔离/越权/撤权实验。schema 或 signed-looking JSON 通过不能验收。
