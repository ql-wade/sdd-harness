# ADR-0023：将 Comet 目标版本更新为 0.5.1

- 状态：已接受版本选择；运行资格待验证。
- 日期：2026-10-29。
- 决策来源：用户明确要求使用 Comet 0.5.1。

延续 ADR-0019、0020、0021 的边界和原 Change 的唯一 DAG：Comet Classic 是业务唯一主控，TeamAI 仅分发，需求、架构、测试设计独立门禁，Kp 阻归档、Kt 阻整体完成。使用原生 `/comet` 和五个阶段 Skill；Matt 方法、独立测试设计与验收不因升级改选 Superpowers。Docker 仅保留必要基础设施。Minicraft 仅作为案例，F10 跨机器正向另期。

官方 [0.5.1 发布说明](https://github.com/rpamis/comet/releases/tag/0.5.1) 与 npm 归档均指向 `35c9860b77b42bafa0c2d80d8d695889f888a924`。来源与归档字节的独立核对记录在 `worker-reports/2026-10-29-comet-051-adoption/`；源码归档 SHA 是本机实测，不是上游签名，也不证明源码与 npm 包可重现一致。

官方 0.5.1 恢复功能增强，但 resolver 仍在 archived 后直接返回 completed；扩展检查点不包含归档后位置。现有 0005 对该版本仅文本试应用通过，它只实现可选 Kt 读侧谓词，不实现可信状态写入或发布恢复；不得据此声称 Kt 已完成。由原 P2_4/P1_3/P4_6 完成最小受控接入，并以真实同 Run、归档、发布、权限与恢复证据验收。

0.5.1 的官方 Classic 方法说明仍引用 Superpowers。现有应用须验证受控替换、恢复和真实阶段调用仍遵循 Matt 方法；资产清单或模拟调用不构成证明。`validateOutcome` 先于 Run 条件提交，不能在验证器内释放签名或执行外部写入；当前代与来源需通过 Comet 受控机制验证。外部发布采用原操作的幂等、查询及恢复，不能虚称与本地事务原子。

0.5.0 的运行、编译、插件和来源资格只保留原范围；0.5.1 必须重新核对锁定源码、npm 包、补丁、编译结果、各命令与同一 Run 全旅程。版本无关组件的原始测试可作为组件证据，不能转成新版业务 PASS。保留原 39 节点、69 工作包、104 场景和 130 检查身份；本期 103 场景和 129 项检查，F10 保持 NOT-EXERCISED。
