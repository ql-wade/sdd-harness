## 0. 已确认的约束

## 1. 硬门禁放在同一 Runtime 的共同判定函数

原则：角色可以提交产物，不能自行把 gate 或阶段设为通过。状态、gate 回执接纳、失效和恢复只能通过 Runtime 的受约束操作。

拟议最小模块：
- classic-gate-policy：读取固定且可信的必需 gate 集合、输入角色、审查身份要求、适用性、修复预算；不能运行 Builder 当前分支上未经批准的新策略自我放行。
- classic-gate-receipts：校验 Runtime 派发的 execution/attempt、输入摘要、报告引用、结论与阻塞 findings，保存不可变回执及有效性投影。
- classic-gate-evaluate：计算某个动作当前是否允许，以及缺失/失效/阻断原因；无权自己派发、改 phase 或重试外部副作用。

复用现有 Classic/Run 存储、锁、事务、trajectory、artifacts、pending/checkpoint；新增持久字段须进入现有 schema/序列化/迁移与事务范围，不是手工往 YAML 塞几个 accepted 字段。Gate 不是另一个拥有 current-stage 的系统。

所有入口都调用同一前提求值：

| 原生位置 | 扩展责任 |
| --- | --- |
| classic-guard | 正常 guard/apply 消费同一必需 gate 结果，不能用任意成功命令代替 |
| classic-state-command / transitions | 直接 open/design/build/verify/确认转换走相同条件；新修订/回退是声明过的 Runtime 动作，禁用手改 phase 返工 |
| classic-hook-guard | 源码写入前确认 R/A/T/P 对当前基线有效，并校验角色/路径；读/写渠道覆盖需逐宿主实证 |
| classic-resolver / runtime-run / continuation | 从有效证据计算下一动作；先处理阻断/失效，不能 stale 后仍分派旧实现步骤 |
| classic-store / engine Run state | 状态与 gate 接纳/失效按同一可恢复事务更新；不能产生一份显示 pass、一份无法恢复的回执 |
| classic-archive / final completion | 校验 Spec 事务、必需知识/平台结果与当前输入；archived 只说明规格操作，不能直接等于整个任务完成 |
| 受保护 CI | 用固定策略对精确候选/集成 SHA 再验，不相信可编辑工作区里的 passed JSON |

当前源码依据：直接转换在 classic-state-command.js:657 起有独立前提路径；classic-resolver.js:50–56 在 archived 时直接返回 completed；classic-store.js 具有锁与状态事务，Run 主状态在 .comet/run-state.json。需要复用并补齐这些路径，不能只加技能提示。

## 2. 独立审查如何被机器接纳

1. Comet 解析已冻结制品，计算 gate 输入绑定，分配审查 invocation/attempt；执行身份由受管 Driver 登记，不能由报告作者自填 role 获得权限。
2. Driver 启动独立只读审查执行，限定规范/设计/测试意图和允许输出目录。A 审查者不能改设计后自评通过，T 审查者不能改用例/oracle 后自评通过。
3. 审查输出结构化 findings 与原始理由，逐 AC/设计责任/用例指出结论和证据；输出 accepted 仅是待接纳结果，不直接改变状态。
4. Runtime 核对真实派发记录、角色独立性、输入、policy、必需覆盖、报告内容摘要和阻塞项。检查器失败、审查拒绝、缺项、未知、缺能力均不能生成有效 pass。
5. 在结果接纳时重新核对当前输入；审查期间被修改的制品导致旧结果标记 stale，不能覆盖新版本。正常通过进入下一 action，不追加人工“继续吗”。

独立自动审查提供的是可追踪的语义质量判断，不是数学完备性保证。结构/引用检查证明格式和绑定；语义审查判断遗漏、错误 oracle 和设计风险。不能让二者互相替代。

## 3. 回执的最低绑定

拟议回执至少包含：run/change/project、gate_id、policy/checker 版本摘要、input_bindings（资源身份/路径/内容摘要）、依赖 gate 回执摘要、适用 AC/case 集合、Runtime 分配的 execution/attempt、verdict/findings、报告引用/摘要、实际观察来源与时间。

| Gate | 必需输入绑定 |
| --- | --- |
| R 需求 | 目标/范围/非目标/AC/约束与交付目标，确认及授权范围 |
| A 架构 | 当前 R 回执、正式设计/接口/必要 ADR、调查的代码参考基线、风险约束 |
| T 测试设计 | 当前 R/A 回执、TestPack 的测试意图版本、case/AC 映射、oracle、环境与能力义务 |
| P 计划 | 当前 R/A/T、tasks 定义/DAG/写入范围、实现参考基线 |
| V 验收 | 当前候选源码/测试/依赖配置、R/A/T/P、真实环境/工具链、必要命令/业务读回与独立身份 |
| K 项目/团队知识 | 该知识义务的源制品/候选、目标空间/条目 revision、授权/审批、写入及独立读回 |
| 最终收尾 | 当前有效必需回执集合、规格事务预期/实际结果、约定平台/目标环境事实 |

A/P 的“代码参考基线”是它们调查/计划所依据的基线，不是要求每次实现写入后的工作区仍原封不动。允许范围内的实现形成新候选，通常失效 V；不因此循环失效需求和计划。V 才绑定实际冻结候选。规范/设计文件必须显式纳入 Gate 输入，不能依赖默认可能忽略中性 Markdown 的命令快照规则。

首版建议按完整声明制品计算保守摘要，不靠 Agent 自称“只是格式调整”保留回执。tasks 定义与 checkbox 进度要分开；新增/修改任务定义影响 P，正常完成勾选不得让整个计划循环失效。若未来拆分 TestPack 意图/执行记录摘要，须由固定 schema 明确定义，不能临时猜测。

## 4. 接纳与推进的事务边界

- 短锁阶段：读取并校验 Run/基线/有效依赖，登记当前输入和审查/写入意图，分配 attempt，保存恢复信息。
- 长执行阶段：释放状态锁，执行审查、测试或 MCP/CI 操作；不持有文件锁等待网络。
- 短锁接纳阶段：重新读 Run 和全部输入绑定，对照原意图/attempt/policy；一致时接纳回执并更新允许动作，不一致则写 stale/拒绝结果。
- 崩溃恢复：先恢复原生 pending/状态事务，再查询对应 execution 或外部对象；不能仅因没有本地完成回执就重复发布/部署。

状态锁不锁住所有源码写入，也不是隔离安全边界。检查应针对冻结候选；受管写入触发新候选/代际，旧结果不可接纳。最终 CI/合并/部署绑定精确 SHA/digest。普通 Agent 不应拥有修改可信 policy、Runtime 二进制、运维 escape 或发布凭据的权限；同 OS 账户任意写只能作协作约束，不能宣称对抗性不可绕过。

若接纳结果和审计/状态未能一致持久化，进入恢复/阻断，不能展示 accepted 后丢失其依据。需实证现有事务能覆盖新增 gate 记录；不能假设旧事务自动包含新文件。

## 5. 失败返工：Runtime 按固定类型选下一动作

| 拒绝原因 | Runtime 返工路径 | 必须保留/失效 |
| --- | --- | --- |
| R 范围/AC/业务规则缺口 | 留在 Open，需求角色补齐；新业务取舍找 owner | 保留草稿与历史；不允许开始正式架构/实现 |
| A 设计遗漏/边界风险 | Design.architecture-repair；改后独立重审 | 原 R 可仍有效；A 和所有下游失效 |
| T 覆盖不足/弱 oracle/数据不可行 | Design.test-design-repair，交测试作者；独立重审 | A 可仍有效；T/P/V 及依赖其结论的知识回执失效 |
| P 冲突/计划越界 | 留在 Build.plan-repair，不允许产品源码写 | 保留 R/A/T，重做 P 和相关后续证明 |
| V 产品缺陷 | 原生 verify-fail 回 Build，Builder 修复后新候选 | 保留仍适用 R/A/T/P；V 和候选相关知识证明失效 |
| V 发现用例设计缺陷 | 受控 test-intent 修订回 Design 对应动作 | T/P/V 失效，不能在 Verify 悄改测试后报通过 |
| 检查环境/工具缺失 | blocked，环境责任方处理，恢复原检查 | 保留原失败类别；不能计作行为 RED 或把义务标 N/A |
| K 目标写入失败/结果未知 | 恢复原知识动作，先按目标 ID/版本读回 | 不标已沉淀，不重复部署；未知发布不能盲目重发 |
| 授权不足/不可自动处理的风险 | waiting-decision，展示具体对象/摘要/选项 | 阻塞依赖动作；合法且独立的其他工作可按图继续 |

architecture-repair、test-design-repair 等为拟议 continuation/action 名，不是当前 CLI。它们必须落到原 Classic Run，不能另建状态机。原 Classic 只有部分回退事件；新增受控修订/回退动作需同步 transition 表、权限、resolver 和恢复测试。

每种自动返工有固定预算，按 gate/输入版本与问题类型计数；不能用换会话、重开 task 或把级别降为 WARNING 无限重试。达到预算后向人报告阻塞与已尝试证据，不能接受未通过的必需 gate 冒充成功。预算数值待 policy 确定。

## 6. 自动失效：按输入与依赖重算，不等提醒

R09 已确认：首版保守失效，需求或设计变更后全部下游证据失效；不自动推断语义等价复用。

| 变化 | 保留 | 必须失效/阻断 |
| --- | --- | --- |
| 当前任务需求/AC/范围变更 | 旧版本历史 | R 重确认/重审，A→T→P→V 及依赖旧需求的知识/最终收尾全失效 |
| 设计/接口/ADR 变更 | 仍适用的 R | A 重审，T/P/V 及相关知识/最终收尾失效 |
| 用例意图/oracle/必验分母变更 | R 与仍适用 A | T 重审，P/V 及相关知识/最终收尾失效 |
| 实现/测试代码/锁文件或实际环境变更 | 输入未变且仍适用的 R/A/T/P | 当前候选 V 与候选相关知识/交付回执失效；新候选重验 |
| policy/checker/权限版本变更 | 过去版本记录 | 受影响 gate 重算/重验；授权撤销即时阻断后续未授权读取/发布 |
| 仅 tasks 正常完成勾选 | 定义未变的 P | 不重做计划；但勾选本身不证明当前 revision 已通过 |

首版不做未证明的跨版本语义等价复用。输入摘要完全一致且来源/环境/权限仍有效时，可复用本来就仍有效的回执；这是验证原绑定，不是把旧证据自动迁移到新要求。

失效在每次派发、结果接纳、受管写入、转换/恢复和完成判定前求值；文件 watcher 仅作加速。即使 Agent 直接编辑了设计、没有调用“修订”动作，也会因摘要不同被阻断；先登记修订和必要授权，再进入正确返工动作。旧回执不删除，明确“仅支持旧版本”，禁止用过期任务勾选或报告冒充当前有效。

尚未关闭的 Change 可以通过受控修订恢复；已经归档/交付的历史不原地改写为新要求，新需求建新 Change，过去验收继续对应过去版本。既有团队知识可能标记待复查；确定错误/越权的内容阻止继续使用，不能把本轮未确认试验自动覆盖正式知识。

## 7. 归档和最终完成的特殊处理

原 Classic resolver 看 archived=true 返回 completed，不能仅在 archive 外套一个脚本等待知识发布。必须修改同一 Runtime 的最终完成谓词：规格归档成功只产生 spec-closeout 回执，全部适用必需义务有效才返回 completed；否则 next/恢复指向尚缺的收尾动作。

archive 会移动工件并更新主 specs，不能把这些受控预期改动误判为任意漂移。复用规格事务的前置目标摘要、预期结果、实际读回与稳定资源映射；新的规格回执绑定归档后结果。遇到另一 Change 改了目标主 specs，先阻断并重新预演，不覆盖新内容。中断时恢复原事务，不重复归档或丢场景。

是否要求 Outline 正式发布/DeepWiki 刷新/目标环境回执才能关闭，由事前交付 policy 定义；一旦本次列为必需，失败后不能临时取消。R06 已确认：必需项目知识在归档前闭合，必需团队发布可在归档后继续但卡整体完成；其他目标平台范围仍按事前契约。

## 8. 具体最小代码落点（拟议，不是已修改）

新增共用 policy/receipt/evaluate 模块；修改 Classic 的 guard、state-command/transitions、resolver/runtime-run、hook-guard、store/engine schema 与 archive 的调用点。技能资产只负责用正确角色生产输入/消费 continuation，不能替代机器谓词；发布遵守显式快照升级，不改 vendored 正文。

无稳定插件入口时可能需要最小 Runtime 补丁并优先上游贡献。改动范围应以共同不变量为中心，避免每个 gate 复制一套驱动、锁、状态与重试机制。
