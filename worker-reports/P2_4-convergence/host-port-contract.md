- `context(intent)`: synchronous pure projection of already-read current action/source/policy facts. Return complete current ActionBinding, policy, frozen command-bound TestContract, admissionOptions. Admission options contain actual current sourceQualification/environment/purpose, builder and author execution/principal exclusions and an explicit protected clock. - `definitionDigest(text)`: bind the existing P2_1 `taskDefinitionDigest` implementation, including its pinned CommonMark AST. This normalizes real task progress markers only; no second Markdown scanner is embedded in Comet.
- `authorizeWrite(request)`: synchronous pure check of the authenticated harness tool event and original current execution registry. Request includes nativeRunId, project/change and the tool request. Tool/session/role strings alone are untrusted. Return an allowed decision with the original Runtime-issued signed dispatch only after checking actual event ownership/currentness. Native verifies the original HMAC, actual Run and signed allowedPaths, then its own phase/gate premises. Existing non-gate author/Builder actions must originate from Comet's original pending action and lock; this port cannot sign a new grant. The concrete generic author-action launcher binding remains P1_3's integration duty.
- `readResult(intent,submitted)`: asynchronous ORIGINAL launch/artifact readback, outside the state lock. Submitted data is only a proposal, not a source. Read the registered launch's actual report/result/tool trace. Do not launch another review, retry a publish, select a consumer from a path, or trust proposed pass/role. Return the original P2_2 packet with three byte arrays and actual launch/envelope. Unknown completion must reconcile the same execution/operation first.
- `admitEvidence`, `evaluate`: bind the original P2_2 functions. Native forces strict managed policy and derives replay/consumption sets from the original Classic receipts.
- `verifyReview`: synchronous pure validation/query of a PREVIOUSLY completed and authenticated review. A consumes the existing P2_5 grill/exact-quorum adapter result; T consumes independent TestPack sufficiency; V consumes the independent Whitebox/typed result. Missing consumer/record rejects. Long adapter/artifact work occurs before this pure query, outside the lock. Reading a skill, a strong label or a self-authored tally is not sufficient.

Synchronous-function checks do not prove JS purity, OS independence or that a particular method ran. Actual bootstrap code/source/installation and I02 credentials/mount/UID boundaries still require independent qualification.

## Native lifecycle and transaction

1. Original short Classic lock: recover/read the same Run, freeze the protected policy version, observe generation changes, enforce dependencies, register native execution/attempt/epoch/generation and complete signed ActionBinding. The intent is in the existing Classic YAML serialization and transaction.
2. Release lock: the execution driver runs the original authorized action. Later readResult and original collectResult obtain/verify actual source bytes outside the lock. They do not choose the next phase or execute a second business retry.
3. Original short lock: re-read current inputs/policy/generation/latest attempt/epoch/Run. Revalidate the original intent and strict source plus completed semantic record. Atomically commit intent consumption, bound raw entry, receipt and effective validity projection through existing writeClassicState/YAML+Run journal. No independent gate-dispatch file is the new authority.
4. Recorded readback uses the original P2_2 Gate's exact acceptedEntry matching/replay rule. Direct admitEvidence deliberately refuses consumed collections; it must not be redundantly used as the readback route before Gate. Buffer/Uint8Array bytes survive the existing JSON/YAML transaction without rendering/replacing their contents.

Old dispatch files, managed-delivery.v1 receipts and generic/file-K records remain history; they are not qualified new approvals. Requirements/design/test-intent/source-method-policy-environment changes use native monotonic invalidation generations. Pending intents are included even before the first pass receipt, so observed changes followed by byte restoration cannot revive an old attempt. P task/plan definition hashing reuses P2_1; ordinary implementation does not invalidate R/A/T/P definitions.

## Tool byte binding (defensive revision)

The existing `policy` code port now supplies `executionScope`, `controllerEnvironmentDigest` and `openSpecBinding`. No new callable consumer, CLI binding-file flag or environment loader is added. The original delivery_policy freezes these facts. Managed execution refuses a missing or changed binding and uses the captured absolute Node and fixed pinned CLI entry for preview and formal calls. Each call verifies the actual Node, manifest and complete lookup-relevant installation tree before and after execution; import/loader environment variables are removed from the actual child environment.

The local mechanism tests derive their facts from the genuine P1_1 pinned package and actual installation hashes. Their scope is component-mechanism; production qualification refs are null/UNVERIFIED. A production binding is not authorized by a label or ref's shape: P1_3's protected bootstrap must obtain and validate actual current I01/I02 registration, environment/image identity and installation protection before installation. Native shape/hash checks do not substitute for that qualification, OS read-only mounts, UID isolation or protection against an unrestricted privileged writer.

The test material helper only observes bytes and does not issue a standing authorization. Its ordinary data mutations are confined to canonical private copies. The original tool installation is unchanged. Invalid environment locations cannot choose the managed program. The shared implementation preserves unmanaged launch compatibility.
