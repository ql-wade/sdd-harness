# Acceptance handoff template

This is an authoring template, not execution evidence. Replace fields with observed project data or explicitly mark unresolved; do not invent hashes or passing results.

- Scope and trusted project root selected from the user's actual task.
- TestPack path, actual bytes SHA-256, mode/status and unresolved requirement IDs.
- Original requirement/source files and exact identities; cases mapped to requirements, dimensions, tests and public seams.
- Required automated commands and/or approved manual steps, environment/build, persona/data, cleanup and terminal authority.
- Actual author selfchecks: command, full output path/hash, exit code, intended RED vs setup failure; not an acceptance verdict.
- Capability/dependency limits and expected missing observations.
- Independent acceptance owner: inspect original basis and test bytes, freeze acceptance scope, execute original tests/manual flow and collect evidence; return missing/weak tests to test-authoring.
- Re-freeze/re-run when basis, tests, assumptions or acceptance scope changes.
