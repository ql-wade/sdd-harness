# Harness 原生浏览器与 E2E 执行

所有含 UI 的 Debug/Journey/Slice 任务在选具体工具前读此文。本文定义能力与证据，不假设所有 harness 有同一个 SDK；运行时工具说明和用户指定优先。Skill 的自动选择、浏览器可发现、实际操作成功是三个分别验证的事实。

## 1. 能力发现与选择

先检查本次会话实际公开的工具/技能。记录 harness、浏览器后端、目标 URL/环境、文档来源、会话/tab 身份及能力表：导航、DOM/AX、交互、截图、console、请求/响应、trace、隔离上下文、文件导出。未探测写 unknown，调用失败保留报错；未公开的能力不能按普通 Playwright API 猜测。

| Harness / 已发现入口 | 启动与约束 |
|---|---|
| Codex 暴露 `mcp__cua_repl.js` | 遵守其首调用契约：首次只调用一个入口，如 `await cua.getState()`；读返回文档，再选当前 IAB/用户指明 tab。按文档使用 DOM/AX、交互和 `getScreenshot()`；自动展示的图片不要重复 emit。不要把别的 node_repl SDK 混进 cua_repl |
| ZCode 暴露 `control-browser` / browser-use 技能 | 先读会话内该技能，再用其 node_repl、bootstrap 与浏览器 registry。后端与 tab 从当前 inventory 选择，按运行时文档恢复会话；不要照搬 Codex 的 `cua.*`。截图按 ZCode 文档在同一 cell emit；其 IAB 不支持的 API 不得猜用 |
| Claude 或其他 harness 暴露原生浏览器集成 | 先加载其实际技能/工具文档，发现标签页、观察与截图调用；不能凭 harness 名字假设有 IAB 或 Chrome 集成 |
| OpenCode/CLI 没有原生浏览器 | 先检查已配置浏览器 MCP；其次使用仓库已有 Playwright 测试。明确属于外部 runner，不宣称是内置浏览器。没有现有可用工具时报告能力阻塞，必要安装另行说明 |

用户明确指定内置浏览器时，不因另一个 CLI 更方便而换浏览器；若原生缺网络采集，可并行补服务日志/现有测试，但不能把两个不同会话的证据拼成同一次操作。保留 URL/tab/correlation 关联。已有 tab 按本次事实匹配，不取数组首项；保留仍在等待的自动浏览器检查，不因一次观察超时就重建/反复刷新。

## 2. 审查交付计划 → 原生观察 → 独立运行

复用仓库现有测试、fixture、鉴权和服务启动脚本，不为了验收搭第二套测试框架。

1. 审查作者交付的用例 ID、persona、初态/隔离数据、目标构建、逐步动作、DOM/请求预期、终态系统和需求支撑的读回断言。成功路径、相关失败/边界、持久化后的刷新/重入至少分别考虑；无关场景明确 N/A。
2. 服务已运行则验证 URL、健康、环境/构建；需要启动时复用项目脚本，分别等前后端 readiness，捕获日志；端口可连不是业务就绪。只清理由本次启动的进程与测试数据。
3. 打开或复用原生浏览器页，读取实际 DOM/AX，按可见语义定位。动作前观察、动作后断言；弹窗/新 tab 检查真实目标变化，不因源 URL 不变就重复点击。
4. 若任务要求可重复 E2E，核对作者交付脚本的实际定位器、断言和 runner，再独立执行。缺脚本或脚本漂移交回 test-authoring，不现场编写/修改测试。原生浏览器的即时操作可从当前 DOM 选定位器，但不得借此替代缺失的自动化交付。只生成文件或 `--list` 不是执行通过；不混用 SDK API。
5. 接请求观察或真实服务接收日志：method、URL、参数位置/关键字段、响应结果、case/correlation 对齐。服务日志只能证明接收/处理链，不能声称看到了浏览器 console 或全量网络。
6. UI 结果后在效应系统独立回读，检验 durable/异步终态；刷新/重入再次核对，防止仅组件内存改好。只读纯展示任务无需虚构写入/数据库；仅纯函数修复走 Slice 的独立期望值。
7. 运行受影响回归；记录首轮与最终命令/退出码/计数。失败重现后定位根因；修复后新运行不能擦掉原先失败/重试记录。

## 3. 等待与失败交接

按能力用语义 locator、web-first assertion、明确 URL、特定响应或具上界的终态轮询。动作自身可等待可操作性，但不代表业务完成。不要用固定 sleep、document.readyState 或 `networkidle` 作为通用完成判据。

先判断产品缺陷/测试漂移/环境失败，记录证据与责任方。定位器、等待、隔离数据或测试文件问题交回 test-authoring；产品/配置问题交回实现者。验收者不修改这些交付物。不准删断言、把预期改成错误实际值、skip/fixme 必测用例、无限重试直到绿。失败→修复→独立新运行通过可作为新证据；原失败记录仍保留。作者尚未修复的必测用例保持未完成。

trace 仅在工具支持时从首动作前启用到终态后；不存在 trace API 不得虚构。Journey 冻结的 console/network/route-scan、A-J、source 与 provenance 义务不因 SDK 能力少而解除。原生观察通过与完整 Journey 闭合分别报告；缺项按原契约保持未验证。

## 4. 截图捕获、展示与归档

用户要求截图或 UI 验收时，页面加载后、关键操作结果、失败现场捕获实际图像。非视觉的中间探索优先 DOM，避免每步截图。截图展示只是证据交付，不能代替结果断言。

每张图记录 run_id/case_id/step、目标 URL、浏览器/tab、persona/viewport、实际捕获时间、展示/附件引用；工具能导出时还保存真实文件路径及 SHA-256。工具只提供原生图片时引用真实工具图像，不声称已保存本地文件。路径必须存在，禁止占位路径或编造截图。

严格遵守当前工具的图像输出协议：某些工具自动展示（Codex cua_repl），某些要求显式 emit（ZCode）；调用截图却未展示时补正确的图像输出，不把字节数组当图。最终答复嵌入关键截图或原生附件，并链接用户可访问产物。用户指定产物目录优先，否则使用工作区的 outputs/whitebox-verify/<run_id>/，截图前避开凭证/私人数据。

报告截图清单同时列 DOM/请求/终态证据的引用。截图缺失但用户要求了截图时，交付仍未完成；不能用“DOM 正确”代替，也不能下载其他运行截图拼接本次证据。

## 5. 能力缺口与判定

逐项报告 navigation/interaction/DOM/screenshot/console/network/trace 的 observed、unsupported、unknown 与原始工具输出。缺功能先寻找同一 harness 已公开的支持路径，再考虑现有回退；一次瞬态失败不是“工具未安装”。

- Debug：未验证维度使用 UNVERIFIED+原因证据；不冒充 PASS。
- Journey：沿用 journey-contract.md；缺任何强制原始证据，保持未闭合。IAB 真实操作、服务日志和截图均可保留为部分证据，不能冒充完整 browser-report/route-scan。
- Slice 无 UI：浏览器/截图不适用；按源码依据记录，使用本地 RED/GREEN/回归证明，不引入无关浏览器或数据库。
- 全部浏览器不可用：保留后端/API/静态检查与工具失败证据，UI 未验证；不把 curl 或构建通过称完整 E2E。
